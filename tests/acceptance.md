# 对话体验验收

这些是需要在实际宿主中完成的行为场景，不以匹配固定回答或检查 SKILL.md 字符串代替。自动化文件测试只覆盖存储和包构建。至少在两种宿主验证后，才能声明对应对话体验已验证。

所有持久化实验使用单独的临时 `SONG_DEEP_DIVE_DATA_DIR`，不要修改真实个人偏好。测试真实歌曲背景时使用宿主实际可用的检索，记录来源；没有网络的场景不得伪造访谈。

| 场景 | 输入／前提 | 观察点 |
| --- | --- | --- |
| 不触发 | 新对话只说“我最近很迷茫” | 不主动推荐歌，也不问歌手偏好。 |
| 首次心情入口 | “我最近很迷茫，有哪些歌曲能给我指引？”；无记忆文件 | 一次询问喜欢的歌手，可跳过；原问题不丢失。 |
| 首次单曲推荐 | “调用这个 Skill，给我推荐一首歌”；先回答喜欢的歌手 | 偏好回答后同一轮推荐一首并完整解读，不只给短简介。 |
| 跳过后续接 | “给我推荐一首歌”；首次询问时回复“跳过” | 推荐并完整解读一首，不重复询问偏好。 |
| 候选选中 | 先给 2—3 个候选，用户回复“第二首” | 当轮解读对应作品，不再给一句介绍或询问要不要解读。 |
| 已有偏好 | 记忆已保存 Taylor Swift；同一心情请求 | 2—3 个候选有具体联系，优先考虑熟悉歌手，不能断言听过。 |
| 每日发现 | “给我今天的歌曲推荐”；有近期记录 | 排除近期展示作品，允许其他歌手，不探问心情。 |
| 指定作品 | “我想了解 evermore 在讲什么”；首次流程已完成 | 直接完整解读；关键歌词短引与释义在眼前；约三个具体后续方向。 |
| 文章式细读 | “深入讲讲林俊杰的《修炼爱情》”；联网可用 | 以具体读法开篇，可信歌曲信息适合时用“项目｜内容”表格呈现，依来源讲背景并按段落细读；用清楚的 Markdown 标题组织，篇幅随资料与歌曲复杂度展开，文章有主线、不只给短评；编曲、MV 等只在核实后纳入。 |
| 片段先于拆词 | 同上，或用户提供想读的歌词片段 | 细读先展示有完整语意及必要相邻句的歌词片段，再分析片段中的用字与句间联系，展开画面和情绪并回到前后文；不先概括原句再只引一个词，也不以词条目录取代段落阅读。 |
| 引用额度有限 | 同上，宿主限制歌词短引量 | 在允许额度内集中读透更少的连贯片段，其余段落概述衔接；不因额度有限将每节歌词都削成孤立词语，不超额引用或近似重现全词。用户已提供的片段按适用规则处理。 |
| 语气与收束 | 同上 | 解释具体词句而非教导听众“接纳、原谅、继续爱”；结尾回扣已分析的歌词，不以通用成长道理替代作品理解。 |
| 可核对的来源 | 同上，声称已核实背景或表格信息 | 链接指向实际打开且支持该事实的作品／访谈具体页面；平台首页、搜索结果或缺少内容标识的地址不算核实来源。 |
| 证据与强主张 | 同上 | 不把“没有资格悲伤”等标题判断当事实；区分创作者一手讲述、媒体转述与文本读法，不为叙事补造具体细节。 |
| 短回复跟进 | 收到不完整推荐后说“好” | 将歌曲视为已选中并立即补上完整解读。 |
| 完成后的确认 | 已完成完整解读后说“好，谢谢” | 不重复长篇解读。 |
| 明确只要短推荐 | “推荐一首，只要歌名和一句理由” | 尊重用户篇幅要求，不强制长篇解读。 |
| 心情后的解读 | 用户在心情入口选中一首 | 开头、相关歌词、收束有具体联系；没有心理诊断与泛化劝导。 |
| 自由追问 | “为什么她要写这首歌？” | 直接深入动机；不重新选歌、询问偏好，不用未知经历凑故事。 |
| 另一作品 | “讲讲 Ariana Grande 的 ghostin” | 核实署名与本人表述；人物推测与事实分清，叙事结构随作品变化。 |
| 中文歌曲 | 指定一首中文歌 | 以中文词义、意象和背景展开，不强行套用英文语法分析或希望转折。 |
| 没有网络 | 宿主不可搜索，用户给出歌词片段 | 说明背景无法在线核实，基于提供文本解读；不伪造链接。 |
| 数据不可读／损坏 | 权限被拒绝或 JSON 损坏 | 原文件不覆盖；本次可继续，避免声称长期记住。 |
| 数据只读 | 能读不能写 | 使用旧偏好与记录，新增内容仅本会话；限制说明简短。 |
| 跨 Agent | 同一临时数据目录，切换宿主 | 沿用同一偏好，排除近期候选；不把推荐记录说成听歌历史。 |
| 明确重访 | “昨天那首再讲一遍” | 正常重访，不被去重机制拒绝。 |
| 清空请求 | “忘掉我的歌手偏好” | 只清空歌手；除非要求全部，否则保留其他字段。 |

记录宿主名称、版本、安装方式、检索能力、文件能力和实际结果。安装目录里存在文件只证明安装成功，不证明上表场景已经通过。

## 已观察的失败与复验状态

Codex 中使用 v0.1.0 时，首次请求推荐一首、回答歌手偏好后，只收到歌曲名、一句歌词的短评和官方 MV 链接；接着回复“好”，只得到告别语。缺失歌词细节之间的解释、全曲主线和后续深入方向，单曲推荐与短回复跟进两项均未通过。

v0.1.1 补充了单曲推荐与候选选择后的解读交付规则，但后续人工测试显示，文章仍太像短评，欠缺清晰主张、歌曲信息表和按段落推进的细读。v0.2.0 增加了文章结构、信息表与分节。用户回传的《修炼爱情》回复已有这些层次，但歌词分析主要仍是抽象的情绪与成长判断；只引用歌名，缺乏从具体字词展开的阅读。回复还以不完整的平台地址和搜索结果页充当来源。字词细读与有效来源仍未通过。

v0.2.1 将细读改为从措辞、意象搭配与句间变化展开，加入两个短示范，收束回到作品，减少泛化劝导和重复的谨慎声明，并明确禁止占位地址或搜索页冒充核实来源。用户回传的回复已分析具体用字，但细读被拆成“放好／养／点亮／原谅／投降”等词条；每节只引用一个词，再用自己的话概括原句，仍未让用户读到有上下文的歌词。片段呈现与段落阅读尚未通过。

v0.2.2 将阅读单元改为一小段连贯歌词，明确先展示原句及必要的相邻句，再分析其中的词与句间关系；示例同步改成片段在前的完整小节。引用额度有限时集中阅读更少的连贯片段。格式与打包测试不能证明对话效果已修复；新版行为仍待真实对话复验。
